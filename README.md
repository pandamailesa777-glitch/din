# Анализ вертикальной динамики конструкции

Python-программа для предварительного исследования вертикального движения
абсолютно твёрдого тела на горизонтальном основании. Вычисляет отрыв,
максимальную высоту, скорость и ускорение, время и скорость первого касания.
Простой интерфейс Tkinter, пять графиков Matplotlib, экспорт CSV и PNG.

## Быстрый запуск на этом компьютере

Окружение `.venv` уже создано, зависимости установлены и проверены.
Откройте `run_gui.bat` двойным щелчком. В окне программы:

1. Нажмите **Конфигурация JSON** и выберите `examples/config.json`.
2. Нажмите **Нагрузка CSV** и выберите `examples/force.csv`.
3. Нажмите **Выполнить расчёт**.
4. Просмотрите вкладки **Графики** и **Итоговые результаты**.
5. При необходимости нажмите **Экспорт CSV** или **Сохранить PNG**.

В примере используется искусственная прямоугольная сила 196,2 Н,
направленная вверх, для тела массой 10 кг, с 0,2 до 0,7 с.
Это учебная нагрузка, не связанная с реальным пусковым оборудованием.

Результаты примера: высота 2,4525 м; скорость вверх 4,905 м/с;
первое касание в 1,907106781 с со скоростью −6,936717523 м/с.
Готовые графики и таблицы находятся в `output/`.

## Установка на другом компьютере

Требуется Python 3.10 или новее. В установщике Python для Windows включите
компонент **Tcl/Tk and IDLE**. Команды PowerShell из папки проекта:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m vertical_dynamics
```

Если команда `py` отсутствует, используйте `python` из вашей установки Python.
На Linux может потребоваться системный пакет `python3-tk`; команды окружения
используют `.venv/bin/python`. Для запуска интерфейса нужен рабочий стол.
Консольный расчёт и создание PNG работают без графического дисплея.

Проверенные точные версии зависимостей, включая средства тестирования,
сохранены в `requirements-tested.txt`. Для воспроизведения проверенного
окружения используйте этот файл вместо `requirements.txt`.

## Консольный запуск

```powershell
.\.venv\Scripts\python.exe -m vertical_dynamics --config examples/config.json --force examples/force.csv --output output
```

Аргументы `--config` и `--force` обязательны для консольного расчёта.
Без аргументов запускается интерфейс. Вариант с предварительной загрузкой:

```powershell
.\.venv\Scripts\python.exe -m vertical_dynamics --gui --config examples/config.json --force examples/force.csv
```

CLI перезаписывает одноимённые результаты в выбранной папке; для сохранения
нескольких запусков задавайте разные `--output`. GUI создаёт новую подпапку
для каждого экспорта CSV. Выбор другого входного файла сбрасывает прежние
результаты, чтобы не экспортировать расчёт для старых данных.

## Входные данные и единицы

Конфигурация — JSON в UTF-8 с разделами `parameters` и `solver`.
Каждая размерная величина имеет вид `{"value": 10, "unit": "kg"}`.
Обязательны все поля из примера; физические параметры не подставляются
автоматически. Неизвестные поля отклоняются, чтобы опечатки не скрывались.

| Поле parameters | Значение | Допустимые единицы |
|---|---|---|
| `m` | Масса, строго положительная | `kg`, `g`, `t` |
| `g` | Ускорение тяжести, строго положительное | `m/s^2`, `mm/s^2` |
| `Vz0` | Начальная скорость, плюс вверх | `m/s`, `mm/s` |
| `z0` | Начальная высота над основанием, неотрицательная | `m`, `cm`, `mm` |
| `t0` | Начало приложения внешней силы | `s`, `ms` |
| `t1` | Конец приложения внешней силы | `s`, `ms` |
| `tmax` | Максимальное время расчёта | `s`, `ms` |

Требуется `0 ≤ t0 < t1 ≤ tmax`. Начальные условия заданы в `t = 0`.
При `z0 = 0` отрицательная начальная скорость не допускается: она означает
начальный удар, который эта версия не моделирует.

| Поле solver | Назначение | Единицы |
|---|---|---|
| `max_step` | Максимальный внутренний шаг интегрирования | `s`, `ms` |
| `output_step` | Основной шаг таблицы/графиков | `s`, `ms` |
| `rtol` | Относительный допуск, число от 1e-12 включительно до 1 | Безразмерное число |
| `atol_z` | Абсолютный допуск по высоте | `m`, `cm`, `mm` |
| `atol_v` | Абсолютный допуск по скорости | `m/s`, `mm/s` |

Шаги и абсолютные допуски строго положительны. Все числа должны быть конечными.
Основная сетка вывода ограничена миллионом интервалов; к ней добавляются
узлы нагрузки, события и точки экстремумов. `output_step` не задаёт точность
интегрирования и не ограничивает точность поиска максимумов.

CSV содержит ровно два столбца, разделённых запятой, с десятичной точкой:

```csv
time[s],Fz[N]
0.2,196.2
0.7,196.2
```

Поддерживаются `time[s]` или `time[ms]` и `Fz[N]` или `Fz[kN]`.
Нужны минимум две точки, строго возрастающее время и полное покрытие
`[t0, t1]`. Повторы времени, пустые/нечисловые значения, NaN/Infinity и
несовместимые единицы отклоняются. CSV не сортируется автоматически.

Между узлами применяется **линейная интерполяция**. Вне `[t0, t1)` сила
равна нулю. Поэтому две одинаковые точки в примере образуют прямоугольный
импульс со скачками на границах. Внутренние скачки силы в текущем CSV-формате
не поддерживаются; повторять одну временную отметку для скачка нельзя.
Дополнительные точки за пределами `[t0, t1]` на силу вне интервала не влияют.
Для задачи без воздействия задайте CSV с нулевой силой.

`Fz` — внешняя сила **на тело**, без силы тяжести и реакции основания.
Плюс означает вверх, минус — вниз. Тяга двигателя не преобразуется в эту
силу: для такого преобразования нужна отдельная модель передачи усилий.

## Физическая модель и результаты

В контакте `z = v = 0` и реакция `N = mg − Fz`, пока `Fz ≤ mg`.
Если сила превышает вес, тело отрывается. В полёте `N = 0`,
`dz/dt = v`, `dv/dt = Fz/m − g`. Опоры не создают удерживающей силы.
После окончания воздействия полёт продолжается под действием тяжести.
Решатель SciPy RK45 останавливается при первом пересечении основания вниз.

Временной интервал разбивается по узлам CSV, скачкам и нулям скорости.
Это позволяет обнаружить короткий импульс и предотвращает пропуск касания
между двумя шагами с положительной высотой. Внутри каждого участка сила
линейная, скорость квадратичная; её корни дают экстремумы высоты. Нули
ускорения дают экстремумы скорости. Максимумы не зависят от шага вывода.

Таблица различает максимальную скорость со знаком и максимальный модуль
скорости; аналогично для ускорения. Высота — абсолютный зазор над основанием,
а подъём относительно `z0` приведён отдельной строкой. Ускорение при ударе
не вычисляется. На разрывах силы учитываются односторонние пределы ускорения.

Если тело уже находится над основанием в начале, момент предшествующего
отрыва неизвестен, и это явно отмечается. Время полёта тогда отсчитывается
с начала расчёта. Если касание не наступило до `tmax`, его время и скорость
остаются пустыми с пояснением; нули вместо отсутствующих данных не подставляются.

Выгружаются:

- `time_history.csv`: `time_s`, `z_m`, `vz_m_s`, `az_m_s2`, `Fz_N`,
  `reaction_N`, `state`, `contact`.
- `summary.csv`: ключ показателя, русское название, значение, единица и примечание.
- `run_metadata.json`: использованные параметры в СИ и исходная нагрузка в СИ.
- `plots.png`: пять графиков с отметками отрыва и касания, при консольном запуске;
  в интерфейсе сохраняется отдельной кнопкой.

В CSV `state` принимает значения `contact`, `flight`, `touchdown`.
Строка `touchdown` содержит скорость, ускорение и силу непосредственно до
удара, высоту 0 и пустую реакцию: ударная реакция неизвестна.
В других строках значения на скачках силы берутся справа.
CSV записывается в UTF-8 с BOM; при импорте в Excel выбирайте разделитель
«запятая» и десятичный разделитель «точка».

## Ограничения

Одна степень свободы, абсолютно твёрдое тело, неподвижное плоское основание.
Модель не учитывает упругие деформации, вращение, частичный отрыв опор,
опрокидывание, скольжение, взаимодействие движущегося изделия с установкой,
последующие удары и отскоки. Контакт определяется с численной точностью,
задаваемой допусками; почти касательное сближение чувствительно к погрешностям.

Результаты нельзя использовать для подтверждения безопасности реальной
пусковой системы без независимой инженерной проверки.
Полное описание уравнений и соглашений: [docs/MODEL.md](docs/MODEL.md).

## Проверки

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe tools/check_reference.py
.\.venv\Scripts\python.exe tools/check_gui.py
```

Последняя команда требует рабочего стола и проверяет Tkinter в скрытом окне:
загрузку, фоновый расчёт, графики, таблицу, экспорт и сброс старых результатов.
Она не входит в обычный набор pytest, который работает без GUI.
В ограниченной песочнице Tcl/Tk может не инициализироваться; запускайте
проверку интерфейса в обычном пользовательском сеансе.

Итоги: **48 автоматических тестов пройдены**, отдельная проверка GUI пройдена.
Численная проверка шага сохранена в `docs/validation_results.json`.
Подробности: [docs/VALIDATION.md](docs/VALIDATION.md).

```text

  model.py         Уравнения движения и закон контакта
  solver.py        Численный решатель, события и экстремумы
  results.py       Таблицы, обработка и экспорт
  plotting.py      Пять графиков и PNG
  gui.py           Tkinter и фоновый расчёт
  __main__.py      Командная строка и запуск интерфейса
tests/             Эталонные и регрессионные тесты
examples/          Конфигурация и искусственная нагрузка

```
